1. Breadth-First Search (BFS)

Simple Explanation:

Imagine you're exploring a maze level by level, like peeling an onion. BFS explores all nodes at the same distance from the start before moving to nodes further away. It's like water spreading evenly in all directions.

Real-world analogy: Like exploring a building floor by floor, checking all rooms on the 1st floor before going to the 2nd floor.

How it works:

  • Uses a queue (First In, First Out - like people waiting in line)
  • Explores nodes level by level (all nodes 1 step away, then 2 steps, then 3, etc.)
  • Guarantees finding the shortest path (in terms of number of steps)
  • Complete and optimal for unweighted graphs

async function BFS(graph, start, goal) { const queue = [[start, [start]]]; // Queue: [node, path] const visited = new Set(); // Track visited nodes const steps = []; // Record steps for visualization while (queue.length > 0) { // Remove from front of queue (FIFO) const [current, path] = queue.shift(); if (visited.has(current)) continue; visited.add(current); // Check if goal reached if (current === goal) { return steps; } // Add all unvisited neighbors to the BACK of queue const neighbors = Object.keys(graph[current] || {}); for (const neighbor of neighbors) { if (!visited.has(neighbor)) { queue.push([neighbor, [...path, neighbor]]); } } } return steps; // Goal not found }
Key Points:
  • queue.shift() - removes from front (FIFO)
  • Explores nodes in order of distance from start
  • Shortest path guaranteed (in steps, not cost)

2. Depth-First Search (DFS)

Simple Explanation:

DFS explores as far as possible along each branch before backtracking. It's like following one path all the way to the end, then going back to try other paths.

Real-world analogy: Like following a maze by always turning right and keeping your hand on the wall - you'll explore everything eventually but might take a long path.

How it works:

  • Uses a stack (Last In, First Out - like a stack of plates)
  • Dives deep into the graph before exploring siblings
  • Doesn't guarantee shortest path
  • Uses less memory than BFS in some cases
  • May get stuck in infinite loops without proper checks

  • stack.pop() - removes from top (LIFO)
  • Explores one branch completely before trying others
  • May not find shortest path
  • Can use recursion as an alternative

3. Uniform Cost Search (UCS)

Simple Explanation:

UCS finds the path with the lowest total cost, not just the fewest steps. It explores nodes in order of their total cost from the start, always picking the cheapest next option.

Real-world analogy: Like finding the cheapest route on a map where roads have different toll costs - you always take the route with lowest total cost.

How it works:

  • Uses a priority queue (always processes lowest cost first)
  • Considers edge costs/weights
  • Guarantees finding the optimal (lowest cost) path
  • Like Dijkstra's algorithm without a destination heuristic
  • Complete and optimal for weighted graphs

async function UCS(graph, start, goal) { // Priority queue: [cost, node, path] const queue = [[0, start, [start]]]; const visited = new Set(); const steps = []; while (queue.length > 0) { // Sort by cost (lowest first) queue.sort((a, b) => a[0] - b[0]); // Remove node with lowest cost const [cost, current, path] = queue.shift(); if (visited.has(current)) continue; visited.add(current); // Check if goal reached if (current === goal) { return steps; } // Add neighbors with their cumulative costs const neighbors = Object.keys(graph[current] || {}); for (const neighbor of neighbors) { if (!visited.has(neighbor)) { const edgeCost = graph[current][neighbor]; const newCost = cost + edgeCost; queue.push([newCost, neighbor, [...path, neighbor]]); } } } return steps; // Goal not found }
Key Points:
  • queue.sort() - orders by cost before selection
  • Tracks cumulative cost from start (g-cost)
  • Always expands lowest-cost node first
  • Optimal path guaranteed (in cost, not steps)

4. Greedy Best-First Search

Simple Explanation:

Greedy search uses heuristics (educated guesses) to always choose the node that "looks" closest to the goal, even if it's not actually the cheapest path overall. It's like always heading toward a visible destination.

Real-world analogy: Like navigating to a visible mountain - you always walk toward it (heuristic), but this might not be the best route if there's a better path that goes around obstacles.

How it works:

  • Uses a priority queue based on heuristic values (h)
  • Always picks node with lowest heuristic estimate
  • Fast but may not find optimal path
  • Requires heuristic function (estimated distance to goal)
  • Can get stuck in local minima

async function Greedy(graph, start, goal, heuristics) { // Priority queue: [heuristic, node, path] const queue = [[heuristics[start] || 0, start, [start]]]; const visited = new Set(); const steps = []; while (queue.length > 0) { // Sort by heuristic (lowest first) queue.sort((a, b) => a[0] - b[0]); // Remove node with lowest heuristic const [h, current, path] = queue.shift(); if (visited.has(current)) continue; visited.add(current); // Check if goal reached if (current === goal) { return steps; } // Add neighbors with their heuristic values const neighbors = Object.keys(graph[current] || {}); for (const neighbor of neighbors) { if (!visited.has(neighbor)) { const hValue = heuristics[neighbor] || 0; queue.push([hValue, neighbor, [...path, neighbor]]); } } } return steps; // Goal not found }
Key Points:
  • Uses only heuristic (h) for decisions
  • Doesn't consider actual path cost (g)
  • Fast but not guaranteed optimal
  • Requires good heuristic function
  • Example: Manhattan distance, Euclidean distance

5. A* Search

Simple Explanation:

A* is the best of both worlds! It combines the actual path cost (like UCS) with a heuristic estimate (like Greedy) to find the optimal path efficiently. It uses f = g + h, where g is real cost and h is estimated remaining cost.

Real-world analogy: Like GPS navigation that considers both:
  • How far you've traveled (g - actual cost)
  • How far you still need to go (h - estimated distance)
  • Always choosing the route with lowest total estimated time

How it works:

  • Uses a priority queue based on f = g + h
    • g = actual cost from start (like UCS)
    • h = estimated cost to goal (heuristic, like Greedy)
    • f = total estimated cost (g + h)
  • Guarantees optimal path if heuristic is admissible (never overestimates)
  • More efficient than UCS (explores fewer nodes)
  • More accurate than Greedy (considers actual costs)

async function AStar(graph, start, goal, heuristics) { // Priority queue: [f-value, g-cost, node, path] const queue = [[heuristics[start] || 0, 0, start, [start]]]; const visited = new Set(); const steps = []; while (queue.length > 0) { // Sort by f-value (lowest first) queue.sort((a, b) => a[0] - b[0]); // Remove node with lowest f-value const [f, g, current, path] = queue.shift(); if (visited.has(current)) continue; visited.add(current); // Check if goal reached if (current === goal) { return steps; } // Add neighbors with their f, g, and h values const neighbors = Object.keys(graph[current] || {}); for (const neighbor of neighbors) { if (!visited.has(neighbor)) { const edgeCost = graph[current][neighbor]; const newG = g + edgeCost; // Actual cost from start const h = heuristics[neighbor] || 0; // Estimated cost to goal const newF = newG + h; // Total estimated cost queue.push([newF, newG, neighbor, [...path, neighbor]]); } } } return steps; // Goal not found }
Key Points:
  • f = g + h (actual cost + estimated remaining)
  • Optimal if heuristic is admissible (h ≤ actual cost to goal)
  • Most efficient optimal algorithm
  • Balances exploration vs exploitation

Algorithm Selection Guide

Use BFS when:

  • You need shortest path in steps (unweighted graph)
  • Graph is small and shallow
  • You want to explore level by level

Use DFS when:

  • Memory is limited
  • You just need to find ANY path (not optimal)
  • Graph is very deep

Use UCS when:

  • Edges have different costs/weights
  • You need optimal cost path
  • No heuristic available

Use Greedy when:

  • You have a good heuristic
  • Speed is more important than optimality
  • Approximate solution is acceptable

Use A* when:

  • You have both edge costs AND a good heuristic
  • You want optimal solution efficiently
  • Best general-purpose search algorithm

Key Terminology

  • Frontier/Open Set: Nodes discovered but not yet explored
  • Visited/Closed Set: Nodes that have been fully explored
  • Heuristic (h): Estimated cost from a node to the goal
  • Path Cost (g): Actual cost from start to current node
  • F-value (f): Total estimated cost (g + h)
  • Optimal: Guarantees best solution
  • Complete: Guarantees finding solution if it exists

Summary

All these algorithms search a graph to find a path from start to goal, but they differ in:

  1. Order of exploration (queue vs stack vs priority)
  2. What they consider (steps, costs, heuristics)
  3. What they guarantee (optimality, completeness)
